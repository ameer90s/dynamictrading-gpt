### 2) الأخبار وCatalyst
- Netlify Scheduled Function منفصلة اسمها `news-scan` تعمل في دقائق مختلفة عن مسح الأسعار حتى لا تتعارض مع حد API المجاني.

### 3) Expectation قبل اعتماد الصفقة
كل صفقة تنفيذية تحسب:
- Expected R لكل صفقة.
- Estimated Win Rate.
- مصدر التقدير.

High Precision يرفض الصفقة إذا كان Expected R أقل من +0.20R.
Balanced يرفضها إذا كان Expected R أقل من +0.08R.

عند عدم وجود سجل كافٍ يستخدم النظام Prior محافظ. مع تراكم نتائجك يستخدم Bayesian shrinkage ويخلط:
- الأداء العام.
- أداء السهم نفسه.
- أداء وقت التوصية.
- أداء نطاق الثقة.

الهدف منع تضخيم نسبة النجاح بسبب عينة صغيرة.

### 4) Adaptive Exit + Trailing Stop
بدلاً من T1/T2/T3 ثابتة دائماً يوجد 3 Profiles:

**TREND_RUNNER**
- T1 = 1.0R
- T2 = 2.0R
- T3 = 3.2R
- بعد T1 → نقل SL إلى Break-even.
- بعد T2 → Trailing على آخر Swing 5m.

**STANDARD**
- T1 = 1.0R
- T2 = 1.7R
- T3 = 2.5R

**DEFENSIVE**
- T1 = 0.8R
- T2 = 1.4R
- T3 = 2.0R
- يستخدم في السوق المحايد أو إذا المساحة أمام السعر محدودة.

البرنامج لا يزيد نسبة المخاطرة أو حجم الصفقة تلقائياً.

### 5) تحليل أسباب الخسارة
عند تسجيل SL، يتم تصنيف الأسباب المحتملة تلقائياً مثل:
- دخول متأخر / مطاردة.
- Retest أضعف.
- RVOL منخفض نسبياً.
- توافق 1m/5m/15m متوسط.
- مساحة R محدودة.
- Relative Strength غير كافية.
- خبر معاكس.
- Catalyst عالي المخاطر.
- توصية متأخرة.

قسم Error Lab يعرض أكثر الأسباب تكراراً كنسبة من صفقات SL. إذا تكرر سبب واضح في عينة كافية، يرسل الموقع Risk Overrides إلى محرك Netlify ويشدد الفلتر المرتبط به تلقائياً (RVOL / Retest / MTF / Room-R / مطاردة السعر / Relative Strength / الأخبار). التشديد فقط؛ النظام لا يخفف حدود المخاطرة ولا يرفع حجم الصفقة.

### 6) Backtest مختصر داخل الموقع
يوجد قسم Backtest:
- أدخل رمز سهم مثل OKLO.
- يقرأ 5min historical candles للسهم + SPY + QQQ.
- يختبر OR15 → Breakout → Retest → Confirmation + VWAP/RVOL + اتجاه السوق + Adaptive Exit.
- يعرض: Trades, Win Rate, Expectancy, Profit Factor, Net R, Max Drawdown.
- يفصل آخر 30% من الصفقات كـ Out-of-sample بسيط ويعرض OOS Expectancy وOOS Win Rate، مع فحص ثبات النتائج عبر 3 فترات زمنية.

مهم: هذا Backtest تقريبي على 5 دقائق، وليس بديلاً عن Backtest احترافي tick-by-tick أو Walk-Forward مؤسسي. لا يشمل العمولة أو الانزلاق السعري ولا يعيد بناء الأخبار التاريخية.

- يمكن تثبيت BAD TRADE للمتابعة/الاختبار فقط حتى تبقى هي الإشارة الوحيدة الظاهرة لليوم.
- نتائج BAD TRADE تُحفظ في السجل بعلامة BAD لكنها **مستبعدة من adaptive weights وPerformance Calibration وError Lab الأساسي** حتى لا تفسد تعلم High Precision.
- إذا لم توجد صفقة صالحة حتى نهاية نافذة 14:00 نيويورك، تبقى آخر BAD TRADE المحسوبة هي الإشارة اليومية النهائية.

> BAD TRADE لا تعني أن الصفقة ستخسر، بل تعني أن الاستراتيجية الأساسية رفضتها لعدم اكتمال شرط أو أكثر. درجة الجودة وWin estimate ليست ضماناً لاحتمال الربح.

## v3.3 — تنبيهات الخلفية (Android / PWA)

v3.3 R3.1 يشغّل `daily-recommendation` على Netlify كل دقيقة داخل نافذة التداول، لذلك المسح لا يعتمد على بقاء صفحة الهاتف مفتوحة. عند ظهور `CONFIRMED BUY` جديد، يمكن إرسال Web Push للهاتف. كما يعمل `outcome-tracker` كل دقيقة، ونطاق UTC موسّع لتغطية EDT وEST بينما الدالة نفسها تتحقق من توقيت America/New_York.

### إعداد مرة واحدة على Netlify
1. ولّد مفاتيح VAPID على جهازك (أو عبر بيئة Node موثوقة): `npx web-push generate-vapid-keys`.
2. في Netlify > Site configuration > Environment variables أضف:
   - `VAPID_PUBLIC_KEY`
   - `VAPID_PRIVATE_KEY`
   - `VAPID_SUBJECT` (مثال: `mailto:you@example.com`)
3. أعد Deploy للموقع.
4. افتح الموقع على Android، والأفضل تثبيته كتطبيق PWA من Chrome: القائمة ⋮ > Add to Home screen / Install app.
5. من صفحة اليوم اضغط `🔔 تفعيل تنبيهات الخلفية` واسمح بالإشعارات.
6. من إعدادات Android > Apps > Dynamic Trading/Chrome > Notifications تأكد أن الصوت مسموح. لا تضع التطبيق في وضع Battery Restricted إذا كنت تريد وصول التنبيه بأفضل موثوقية.

> ملاحظة: صوت Web Push هو صوت إشعارات النظام الذي يسمح به Android/Chrome؛ الموقع لا يفرض ملف صوت مخصص عندما تكون الشاشة مقفلة.

### ما الذي يبقى مقفلاً؟
اعتماد صفقة واحدة يمنع اعتماد صفقة ثانية حتى **يوم التداول الأمريكي التالي**، لكنه لا يوقف الـScanner أو Signal History أو تنبيهات الفرص الجديدة.
